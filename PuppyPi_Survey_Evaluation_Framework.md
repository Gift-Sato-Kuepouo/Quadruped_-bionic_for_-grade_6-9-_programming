## A2. Pre-Camp Skills Check (15 minutes)

*No help, no internet — just what you already know. Guessing is fine!*

**Section 1 — Read the code (1 pt each)**

**Q1.** What does this program print?

```python
for i in range(3):
    print("Woof", i)
```

a) Woof 3
b) Woof 0, Woof 1, Woof 2
c) Woof 1, Woof 2, Woof 3
d) I don't know

**Q2.** What is wrong with this code?

```python
x = 5
if x > 3
    print("big")
```

a) Nothing
b) Missing colon after the `if`
c) `print` is spelled wrong
d) `x` should be a string

**Q3.** What does this program print?

```python
def greet(name):
    return "Hi " + name

print(greet("Puppy"))
```

a) Hi name
b) Hi Puppy
c) Hi Hi Puppy
d) Error

**Section 2 — Concepts (1 pt each)**

**Q4.** A **variable** in programming is best described as:

a) A type of robot
b) A labeled box that stores a value you can change or reuse
c) A loop
d) A kind of sensor

**Q5.** A **sensor** on a robot is used to:

a) Make the robot look cool
b) Measure something about the world (like distance, light, or tilt)
c) Store files
d) Print things

**Q6.** When you **debug** code you are:

a) Deleting the program
b) Finding and fixing problems so it works as intended
c) Adding more comments
d) Turning the computer off and on

**Section 3 — Transfer task (2 pts, rubric-scored)**

**Q7.** Imagine a robot dog that bumps into walls. In your own words, explain one way you could help it avoid walls. You may draw a picture.

*(Scoring: 0 = blank/"I don't know"; 1 = names a vague idea ("make it smarter"); 2 = names a concrete mechanism ("add a distance sensor and make it turn when something is close"))*

**SCORE: ______ / 10**

## A7. Design Journal Rubric

*Graded at Weeks 4, 8, 12 (3 entries minimum). Each dimension 0–3. Total /9.*

| Dimension | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| **Depth of reflection** | Blank or "it was fun" | Describes what happened only | Describes what happened AND why it happened | Analyzes what happened, explores alternatives, asks new questions |
| **Documented failures** | No failures mentioned | Mentions a failure vaguely | Describes a specific failure + one fix attempt | Documents failure → multiple attempts → root cause → generalized lesson |
| **Cross-phase connections** | No connections | Names another phase ("this is like Week 3") | Explains how a skill from an earlier phase is used in the current build | Shows how ≥ 2 prior phases combine into one insight or solution |

**Student's entry score: ____ / 9 × 3 entries = ______ / 27 (final portfolio journal score)**

# PART D — ADMINISTRATION NOTES

1. **Consent:** Send parent/guardian consent for surveys + photo/video (A1 demographics optional; student names pseudonymized in reports).
2. **Timing discipline:** Pre-surveys before any instruction; post-surveys before the showcase *emotions* (or immediately after — but same window for every cohort so data is comparable).
3. **Anonymity:** Exit tickets (A5) and open-ended survey items work best with an anonymous box option — honesty beats completeness.
4. **Data storage:** Keep scored sheets in a restricted folder; report only aggregates. Delete identifiable raw data 12 months post-cohort.
5. **Adaptation:** For K–2 Sprouts track, A2 becomes oral (instructor asks, records answer) and A5 uses emoji-only confidence circles with drawing prompts.
